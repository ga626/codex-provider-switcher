# Signalman AI v0.10.11-alpha

## 让检查结果更容易看懂

- 服务商可用性测试、模型目录和“检查并切换”会先说明现在能否继续、为什么，以及下一步该做什么；HTTP 状态、服务商错误代码和协议字段仍保留在技术详情中，方便需要排障的用户查看。
- 等待上限内没有收到最终结果时，会显示“尚未确认”，而不是直接认定为失败。应用不会擅自重发请求或改写配置；稍后重新检查即可确认服务商的最终状态。
- 模型目录为空只表示当前密钥没有返回可选择的目录，不会据此断定手动填写的模型一定不可用。

## 更安全的服务商切换

- A6、Hiyo、OWL、A18 以及其他标准 OpenAI-compatible 服务商统一使用新版 Codex 的标准认证合同：`auth.json.OPENAI_API_KEY` 配合 `requires_openai_auth = true`。
- ModelFlare 继续只在精确匹配 `modelflare.dev` 时保留其专用 `auth.command` 适配；不会把这套配置写到普通服务商。
- 写入前、切换前和恢复前继续校验受保护的配置指纹，只更新确认属于服务商的字段，避免影响项目、MCP、插件、hooks、记忆、桌面设置和其他认证内容。

## 可读、可排查的本机活动记录

- “全部操作”按时间显示保存、检查、切换、备份与恢复结果，并使用颜色区分完成、尚未确认和需要处理的记录。
- “需要处理”会合并相同原因，显示建议下一步和排查过程；点击“查看诊断详情”可直接阅读完整脱敏诊断包，也可一键复制。
- 本机记录不会保存密钥、配置正文、请求内容或完整响应；诊断包会保留服务商、模型、检查阶段、HTTP 状态、服务商错误代码和关联编号等必要的脱敏事实。

## 已知边界

- 可用性测试只验证当前地址、密钥和模型的最小请求，不能替代长对话、工具调用、额度或第三方服务长期稳定性的实际使用确认。
- GitHub alpha 安装包尚未购买 Windows Authenticode 签名；Windows SmartScreen、Smart App Control 或企业策略仍可能提示或阻止安装。
