# 开发、验证与 PR

本指南只在准备进入 GitHub 时生效。纯本地探索、调试和原型不需要 PR、远端 CI 或 artifact 回执，但仍要按风险做最小检查。

## 四种执行意图

| 用户意图 | 动作 | 停止点 |
| --- | --- | --- |
| 开始修复 | 从主目录最新 `main` 建/切 `codex/<topic>`，实现并跑开发中的定向检查 | 不提交、不推送、不建 PR、不发布 |
| 推进到 PR 前 | 实现、定向验收、提交、干净状态、必要 artifact SHA；在对话内给分开的中文标题和正文 | 默认不推送、不建 PR、不合并、不发布 |
| 推送分支但不建 PR | 在 PR 前状态基础上推送 | 不建 PR、不合并、不发布 |
| 推进到收口 | 推送、建 PR、修复远端检查、合并、验证 `main`、按分类收口 | 未获批准不创建 tag、Release 或 Store 包 |

分支是提交历史；单 PR 默认在主目录直接开发。worktree 只用于并行、外部 worker 或隔离候选，必须位于 `.codex/worktrees/<topic>`，并用 `npm run worktree:manage` 审计和退役。

## 先判定类型

| 类型 | 例子 | 用户验收 | 本地验证 |
| --- | --- | --- | --- |
| 文档/内部维护 | 文案、治理、非运行逻辑 | 无需或截图 | `git diff --check`、相关脚本 dry-run、必要 doctor |
| 普通功能 | 后端、模型目录、配置流程 | 功能 | 受影响的 lint/build/test/smoke |
| 用户可见流程 | 桌面窗口、交互、错误提示 | 功能或截图 | 功能检查 + 开发版窗口 |
| 发布影响 | 入口、安装、升级、版本、Release、用户实际切换/配置写入行为 | 功能或安装发布 | 定向检查 + 最终 artifact 隔离验收 |
| 紧急修复 | 安全、数据损坏、无法启动 | 按风险 | 最小修复 + 回归与回滚证明 |

改变下载、安装、启动、升级、版本、Release、README 下载/使用说明或配置切换行为即为发布影响。安全说明或历史回执本身不因提到安装而自动变为发布影响。

## 本地与 CI 分工

- 本地只跑改动风险需要的检查；不要人工镜像执行完整 GitHub Actions、`npm ci` 或 CodeQL。
- PR 的 `pull_request` CI 和 CodeQL 是远端权威；`main` push CI 用于合并收口。
- 发布影响还要从最终候选 artifact 在隔离环境验证启动、受影响场景和必要桌面流程，回执绑定提交 HEAD 与 artifact SHA256。CI 不能代替人工桌面验收。
- 所有 PR 前检查都记录真实命令、结果和未运行原因；可重复问题不能首次留给 CI。

常用开发版验收：

```powershell
npm run qa:dev-desktop
```

它只打开当前源码，不安装、卸载或升级稳定版。候选安装仅在维护者明确要求验收已合并但未发布版本时，从干净 `main` 运行：

```powershell
npm run qa:refresh-local-candidate -- -Apply
```

## PR 材料与状态

PR 前必须写明：类型、用户验收、本地验证等级、发布结论、实际命令、风险和后续动作。中文标题和正文在对话中分成两个独立代码块；除非仓库要求，不新增材料 `.md`。

| 状态 | 含义 |
| --- | --- |
| 本地候选已验证 | 已完成要求的本地检查和用户验收；可仍有待提交修改 |
| 可提交/可推送 | 提交 HEAD 有对应证据，目标分支最新且工作区干净 |
| PR 远端验证中 | PR 已创建，等待 `pull_request` CI 和评审 |
| PR 可合并 | 必需检查、冲突和评审状态满足仓库规则 |
| 非发布 PR 已收口 | `main` 已验证；本次无新版本或渠道交付义务，既有交付保持有效 |
| 发布影响：代码已合并，产品未交付 | 已合并但批准的版本/tag/渠道验收尚未完成，必须说明暂缓或事故原因 |
| 发布影响：产品已交付 | 同一不可变 artifact 的 tag、Release、远端下载和普通用户验收均完成 |

## 发布与事故

GitHub Release 是日常渠道，Store 是低频稳定渠道；两者分别验收。发生 tag/资产事故时进入 `release incident`：停止新的发布影响 PR，只修 workflow 控制逻辑，从原 tag/原 SHA 受控重跑；不重打 tag、不手工补资产、不混入产品代码。
